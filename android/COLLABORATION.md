# 同一会话的独立 / 协作模式

## 使用

在原有会话顶部点击“独立 ▾ / 协作 ▾”切换执行模式。两个模式共用原来的会话列表、项目、消息区、输入框、附件、上下文和用量统计，不打开协作 Activity，不建立另一条会话。

独立模式将输入交给当前 Agent；协作模式按配置的成员职责分工，把输出、可用的思考摘要、命令 / 工具过程及结果持续写回这条会话。每条输出标注 Agent 和实际模型，成员及尝试编号保留。返回独立模式后这些记录继续可见，下一条任务会携带已有内容。

第一次启用协作时，通过“协作模式”面板进入“协作成员”页配置 2 到 8 位成员。成员编辑按设置行展开：名称、职责、Agent、模型、API 来源、思考强度、权限，以及手机 / 浏览器工具开关。职责可从内置职责中选择，也可自定义并保存为本机常用项；模型列表读取该 Agent 在所选 API 来源中已配置的模型，仍可手动输入模型 ID；思考强度使用“默认 / 关闭 / 低 / 中 / 高 / 极高 / 最大”，权限使用“每次询问 / 自动执行”。相同 Agent 可选不同模型。第一位成员可在其他分工完成后汇总，开关位于“协作成员”页。切换模式和保存成员不调用模型；在原输入框发送消息才提交执行。编辑成员只作用于后续任务，不改写正在执行的配置快照。

消息下方的“本轮协作”打开操作页，页头显示状态与进度；可暂停 / 恢复派发、刷新、停止整轮或单个任务、重试、换执行者 / 模型、检查补丁和确认成果。权限和选择问题继续使用原输入框上方的组件，并按工作流 / 子任务 / 尝试路由。

0.9.5 起，运行中新消息进入统一待发队列；可编辑、删除，或“引入”当前任务调整方向。0.9.7 统一为单一执行按钮：有文字或附件时发送，执行中输入为空时停止，停止后没有可自动接力的普通待发项时，输入为空可继续原任务；队列暂停不影响当前执行。0.9.8 起普通待发消息自动接力，0.9.10 修复发送去重、草稿保留和页面闪烁。详情与三个 Agent 的协议差异见 [队列与引入说明](MESSAGE_QUEUE.md)。

## 切换与记录

正在执行独立任务时可选择结束后切换或停止后切换。协作运行中切回独立模式，后台任务继续，原输入框可以提交独立任务；同项目任务等待工作区和全局名额。停止按钮及本轮操作面板可中断协作，退出确认前不假装任务已结束。

协作输出直接保存为原会话中的一轮，底层独立执行实例不占用共享会话的 CLI binding。模式、成员配置、历史和用量在服务重启后保留；未完成任务暂停且不自动重放。旧版单独协作页生成的记录可回收到它原来关联的会话，保留旧摘要，不创建新会话。

诊断日志与用户消息分开。执行过程独立持久化，每次尝试最多 1000 条 / 4 MiB；原会话每轮显示最新 100 条过程记录，较早过程、旧版缺失或损坏会明确提示。内部生成的 worker 提示词不重复显示为用户输入。旧消息的“编辑”可以带回当前输入框重新提交，原协作记录保留。

## 环境、资源与成果

三个 Agent 共用现有 Ubuntu、Node、Python、Git 与安装文件；每次执行有隔离的配置目录和工作区。不会安装三套系统。相同 Agent 的多个模型可并行；同一成员自己的工作仍顺序执行。

默认全局 2 个运行任务，重任务最多 1 个。设置里的“协作与资源管理”以弹窗调整全局 / 同 API 网关上限。低内存、严重发热、过期资源样本暂停新派发。手机和开发浏览器功能须在成员配置中声明，调度器分配独占资源。第三方 MCP 尚没有完整资源分类。

Git 项目须在仓库根目录、有提交且没有未提交修改；执行使用 worktree，补丁人工检查和合入，不自动提交。后端已支持共享依赖三方合并、连续合入、批量预览与冲突拦截。非 Git 使用上限 200 MiB 的独立快照，成果保存为 ZIP，支持互不冲突的文件交接。工作区约束不是限制全部 shell 行为的安全沙箱。

每次尝试使用固定 API / 模型 / 扩展快照，失败不静默替换模型。用量按执行来源汇总进原会话，DeepSeek 上下文占用不冒充累计计费 Token。模式切换不清零，也不重新发送历史请求。

0.9.4 已提供开发 / 研究 / 并行模板、审核依赖、文件 / 命令验证、有限审核返工、次数 / 时间 / 已上报 Token 预算、已上报限流的来源退避、恢复检查、历史分页、补充要求、结构化交接、合入预览及验收后工作区清理，对应页面入口已接通。

自动最优分工、精确金额预算和长期压力测试仍未完成。补充要求可保存供后续尝试读取；0.9.5 新增队列引入当前执行，Codex 走原生引导，Claude / DeepSeek 走同会话中断续接。普通发送排队等当前协作结束，显式“引入”才影响当前任务。
