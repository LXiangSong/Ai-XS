# Ai-XS 原生 Android App

Ai-XS 与 AI-Web 完全分开，是包名 `app.aixs.mobile` 的独立原生 Android App。
工程使用 Gradle Wrapper、Android Gradle Plugin 和 Google Maven 上的 Material Components for Android。
会话、项目、设置、配置与浏览器预览使用 Android 原生页面；专用 WebView 仅预览开发者提供的项目页面。

## 界面设计

整套界面由 `Ui.java` 一套设计系统驱动（色板、字阶、间距、圆角、描边、涟漪、入场动效），
`NativeUi.java` 在其上提供兼容层，所有二级页面因此共享同一套视觉语言。

- 主题：浅色为雾白底 + 靛蓝主色；深色为近黑底 + 亮靛蓝，并用薄荷绿表示在线/运行状态。
  系统栏透明、跟随深浅色切换图标，键盘与手势条使用同一套 inset 逻辑。
- 首页三段式：56dp 顶栏（菜单、会话标题 + 项目·模型、Agent 胶囊、会话详情）、
  中部对话流、底部输入卡；输入卡为 24dp 圆角，包含项目胶囊、自动增高输入框、
  模型与思考强度胶囊、44dp 圆形发送/停止按钮；输入卡上方的项目胶囊可换目录，
  右侧是权限模式胶囊（询问 / 自动），两者在窄屏会自动让位而不挤压输入框。
- 抽屉 304dp 是会话与项目的浏览器：品牌区、Agent 分段切换、实色「新建对话」、
  「会话 / 项目」两个筛选标签与搜索框；会话按今天/昨天/本周/更早分组，项目按会话数排序，
  点项目即筛选该目录的会话（可一键清除），长按项目设为工作目录；
  项目标签顶部有「新建项目」，可浏览目录或直接输入绝对路径（`projects/add`）。
  底部只保留「工具与扩展」与「设置」，不再重复设置内已有的入口。
- 会话历史为全高 BottomSheet：搜索框、今天 / 昨天 / 本周 / 更早分组，
  长按可重命名、分叉、归档；模型、思考强度、权限与项目选择都使用同类滑动面板并带勾选标记。
- 项目选择不再跳转页面：输入框上方的项目胶囊打开可滑动列表（项目 / 最近使用 / 浏览其他目录），
  选中后下一次任务在新目录开始。
- 上下文用量做成克制的小胶囊，位于发送按钮左侧：一圈 18dp 细环形进度 + 当前占用（如「12.4k」），
  低于 70% 用主色、70% 变警告色、90% 变危险色；没有数据时显示「--」并降透明度。
  点一下打开滑动面板，含占用进度条、最近一轮输入/输出/推理/缓存、本会话累计与压缩标注（数据来自 `usage/read`）。
  运行中另有一行实时状态「Codex 运行中 · 00:42」，两者互不挤占。
- 输入框起步 3 行、最多 9 行，左右内边距收窄，长任务描述不再只能看到一行。
- 权限模式按 Agent 适配：Codex 显示 approvalPolicy 的按需批准 / 自动批准，
  Claude Code 显示每次确认 / 自动接受，DeepSeek 显示询问权限 / 自动执行，
  面板内说明各自的生效机制，切换仍通过 `native/permissions/set` 落到后端。
- 思考过程实时流式显示：客户端直接消费 `item/reasoning/textDelta`、`item/reasoning/summaryTextDelta`
  与 `item/reasoning/summaryPartAdded`，Claude 走增量事件、DeepSeek 走整条 item 增量、
  Codex 走原生通知透传；运行中的思考卡片自动展开并标「思考中」，结束后折叠。
- 向用户提问是独立工具而非文字排版：应用内 MCP 提供 `ask_user`（问题 + 候选方向 + 单选/多选 + 可补文字），
  Agent 调用后阻塞等待，客户端在输入框上方渲染可点的选项卡片，提交结果作为工具返回值交回模型。
  Claude 的 `AskUserQuestion` 与 Codex 的 `requestUserInput` 复用同一张卡片（走 `approvals/respond`）。
  多问题逐项展示，支持上一步 / 下一步并保留各题选项与补充文字，最后提交全部。
  三个 Agent 均可用 MCP 的 questions 数组完成同样的流程；空选择阻止提交，失败时保留卡片重试，过期或中止后移除。
  提问区与输入框同宽，使用 Material 浮起卡片、描边和阴影区分会话；限制高度，长选项在卡片内滚动。
- Skills 与插件使用 Material 卡片库：支持 GitHub 仓库 / tree 目录 / 分支 / Tag / Commit，
  支持从 Android 文件选择器导入 ZIP 或 SKILL.md，并可导入运行环境中的 Skill 目录。
  Skills 的脚本、模板等资源整体保留；每项可指定一个、多个或全部可用 Agent，也可全部停用。
  通用 Skills 通过当前 Agent 的任务要求目录加载，便携插件的 Skills / MCP 按分配注入；
  Claude 插件使用原生 --plugin-dir。未适配的 hooks、commands、LSP、变量配置等组件会提示不兼容，
  不会默默只加载一部分并宣称可用。npm / DeepSeek 原生 bundle 仍由原生安装器管理。
  Agent 可使用内置 extensions_list / preview / import / install / configure 工具操作同一扩展库，
  下一次任务生效。安装不会执行仓库脚本。
- 工具与扩展仅保留 MCP、Skills 与插件。API、环境、Agent 管理与手机诊断分别在设置管理。
  返回按钮和系统返回都保留实际页面层级，API 子页返回设置，日志返回进入前的页面。
- 消息支持复制、Markdown 引用（追加到草稿，不自动发送）、编辑用户原文并重发。编辑保留附件，
  使用当前 Agent 的全新私有上下文，原来的后续保留为“编辑前”分支，已执行的文件操作不回滚。
- 跨 Agent Token 统计按每个私有会话的累计快照汇总并持久保存，重复刷新不重复计数。
  切换后完整历史保留，界面显示“待交接”并能查看上次上下文，发送后才更新当前模型的实际占用。
  会话轮数、步数、耗时只计算当前会话；仅上报上下文的记录不冒充计费用量。
- 停止任务走独立控制队列，不排在文件、命令等耗时请求后；收到结束事件立即更新 UI，
  点击停止后主动核对任务状态；Claude / DeepSeek 取消两秒未结束时清理对应进程，并撤掉等待中的提问。
  主动中断标记“已停止”，不把 Claude 的取消诊断显示为失败。
- 对话排版：用户消息是右对齐气泡（最宽 78%），助手正文直接排版 Markdown，
  代码块为独立卡片（语言标签 + 复制 + 横向滚动），思考、命令、文件改动折成一行，
  展开时显示等宽详情；流式输出带光标，状态行固定 26dp 不挤压对话区。
- 空状态给出图标、标题与三个起手任务；离开底部时出现浮动「回到最新」按钮。
- 二级页面统一为 52dp 返回栏 + 25sp 大标题 + 说明 + 分组卡片 + 11sp 分区标签，
  列表行 58dp（图标块、标题、说明、chevron），连续行自动合并为一张卡片。
- 设置各页重做：首页是状态卡 + 服务 / 能力 / 维护三组带实时副标题的行；
  运行环境页把初始化、检查、修复与日志拆成状态行与操作行；Agent 页每个条目打开管理面板
  （官方安装 / GitHub / 离线导入 / 日志）；设备页用开关行控制页面调试；
  日志页区分普通 / 调试 / 历史，提供来源、操作编号、级别和关键词筛选、行数统计、
  暂停刷新、跳到最新、复制筛选结果与导出脱敏诊断报告，版本号读取自安装包。
- 按压反馈统一：主题 highlight 与按钮 ripple 都改为品牌色低透明度，
  实色按钮使用白色高光，关闭 elevation 动画与默认灰色高亮，波纹按卡片圆角裁剪。
- 启动图标为自适应图标：靛蓝渐变底 + 白色四角星芒（含 monochrome 层），manifest 指向 mipmap。

## 构建

```sh
python android/tools/check_project.py
python android/tools/test_all.py           # 首次联网下载构建依赖
# 缓存完整后可加 --offline；仅构建使用 build.py --lint。
```

普通构建直接使用仓库的固定基础资产，不必重新运行 `prepare_runtime.py`。签名准备、版本维护和分层测试见[开发指南](../docs/DEVELOPMENT.md)。

根项目 Gradle Wrapper 固定 Gradle `8.11.1` 并校验 SHA-256；Android Gradle Plugin 固定 `8.9.3`；
Material Components 固定 `1.14.0`。SDK 平台 35 与 Build Tools 35.0.0，Java 17 源兼容，
JDK 21 构建；优先使用官方 Android SDK Manager 已安装的 SDK/构建工具。

运行 `prepare_runtime.py` 会打包一份 ARM64 Ubuntu、PRoot 与 loader；不读取 AI-Web、用户凭据或历史。
Release APK 使用当前本机 `.state/android-signing/` 密钥，更新必须复用同一签名身份。
本地 APK 路径：`app/build/outputs/apk/release/Ai-XS-<versionName>.apk`，文件名自动带上版本号。

## 行为约定

初始化仅位于 **设置 → 运行环境**。未初始化时首页显示“去设置 / 稍后”提示，不自动初始化，
也没有启动页初始化操作。新 App 的官方与第三方 API 配置为空，不继承设备其他账户。
三个 Agent 共用一套 ARM64 Linux 环境，服务使用 App 私有 stdin/stdout 管道，无 HTTP 工作台。

状态与运行时文件只保存在 Ai-XS App 私有空间。已安装旧版升级时，只在 Ai-XS 私有运行时内迁移其状态。
AI-Web 的代码、服务、API 与资料独立保留，不作为依赖或构建输入。

## 验证与限制

使用 `python android/tools/test_all.py --offline` 执行全部 Python 协议测试、Java 单元测试、Release 构建、完整 Lint 与 APK 签名检查。
测试包含三个 Agent 的会话交接、权限与提问、消息编辑、停止任务、用量、扩展导入及更新维护状态。
手机回归另外覆盖设置返回层级、GitHub 扩展预览、本地导入、AI 安装、实际资源读取、Claude 权限弹窗，以及 App / Agent 更新入口。
自动化测试使用假 Agent 和本地数据，不需要真实 API 密钥；真实第三方 API 的可用性取决于供应商和模型。
多设备、多字号、IME、深浅主题与屏幕阅读器需要持续验收。当前版本是 alpha，不能据此宣称所有设备均无问题。
全量系统日志、其他 App 私有日志及外部浏览器调试不在当前已验证范围。

## 关于与更新

设置 → 关于 Ai-XS 提供版本、GitHub 项目、发布记录、反馈入口和应用更新。
App 从项目 GitHub Releases 检查 APK，下载使用独立前台服务，不依赖 Linux 初始化。
正式 / 测试版按开关选择；下载后验证大小、发布 digest、包名、递增版本代码和签名，再交给 Android 安装。
设置 → Agent 管理 → 检查全部 Agent 更新，也可从单个 Agent 管理页检查。
更新期间保留现有配置和历史；任务运行时拒绝更新，空闲时停止服务、验证并切换新版本，完成后恢复服务。
发布规范见 [UPDATES.md](UPDATES.md)。

## 会话权限模式

输入框上方的“权限”入口支持询问权限和自动执行，三个 Agent 共用同一套会话选择。
询问模式沿用 Agent 的原生授权规则；自动模式允许其自动执行工具，但用户问题仍需回答。
每个 Agent 的新会话默认值与已有会话分别保存，运行中的任务禁止切换；下次任务使用新选择。
Android App 私有空间是隔离边界，本环境未提供额外的 Linux 项目沙箱，界面不提供不可执行的沙箱模式。
DeepSeek 切换模式时新建原生会话并重放已有对话，避免旧会话固定的权限配置覆盖新选择。

## 三个 Agent 共用项目与会话列表（0.7.13-alpha）

项目目录继续由同一套项目登记管理；抽屉与会话面板现在汇总 Codex、Claude Code、DeepSeek 的历史，
按更新时间排序，显示所属 Agent，并支持统一搜索与项目筛选。
列表分页加载完整记录。一个来源读取失败会提示并保留其余来源的结果。
Codex 列表只读其本地索引，不因打开列表而启动 app-server；三者继续共享一套运行环境。

### 同一会话切换 Agent（0.8.0-alpha）

App 独立保存会话正文、项目目录、工具结果和各轮次 Agent 标记。打开旧会话时导入原始记录，
切换 Codex / Claude Code / DeepSeek 保留同一个会话 ID、历史、输入草稿和附件，不启动 CLI。
下一次发送才创建或恢复该 Agent 的原生会话，并交接此前的用户消息、回复、工具结果和附件路径；
历史工具结果只作参考，不重新执行。子会话在列表中合并显示，App 重启仍可继续。
项目与全局要求一并保留，各 Agent 权限单独设置；执行中的任务必须先结束或停止。
交接超过 120000 字符时保留开头与最近历史并提示节选，完整记录仍保存在私有会话文件供 Agent 读取。
部分 DeepSeek 原生 CLI 会话不支持 ACP 回放旧消息，会显示原生限制提示；App 新建会话持续保存完整记录。
重命名、分叉和归档由公共会话层管理，删除只移除 App 会话记录，保留原生 CLI 历史。
外部 CLI 后续对原生会话的改动尚不自动合入 App 已导入的记录。

Codex 模型思考选项从能力目录读取，支持的模型显示极高、MAX、ULTRA 等真实档位，按原值发送。
内置目录来自 Codex 0.164.0 的 model/list；实际启动 CLI 后更新缓存，打开菜单无需启动进程。
未知模型保留低、中、高作为回退；第三方网关是否接受各档位由其接口决定。

### 日志与 Claude 第三方地址（0.8.1-alpha）

日志使用单一滚动区，顶部筛选与底部操作固定。自动刷新只在文件变化时后台读取最近 64 KB，
没有变化不替换正文；手动触碰滚动或选择内容时暂停跟随并保留当前文字，新内容缓存在后台，
点击“跳到最新”恢复跟随。关闭自动刷新后停止读取正文，筛选和复制仍可使用。
日志增量追加时复用已有文字，去除终端颜色控制符，截取时对齐完整行避免 UTF-8 截断乱码。
此页不再提供容易误点的环境检查操作，检查仍位于设置中。

Claude Code 自行追加 /v1/messages，传给它的 ANTHROPIC_BASE_URL 自动去除重复的末尾 /v1，
支持第三方页面填根地址或版本地址，原保存值不变；不影响 Codex 与 DeepSeek。
Claude 未安装时明确引导到 Agent 管理，避免直接显示 subprocess ENOENT。

### 实时任务状态（0.8.2-alpha）

Claude 接入 system/status、api_retry、tool_progress 和流式工具输入事件，分别显示启动、等待接口、
重试次数、思考、准备工具、执行工具、等待确认和输出。任务胶囊显示当前阶段与总用时，
点击可查看最近六次状态、最近事件时间、HTTP 重试码与重试间隔，浮层随运行状态更新。
服务端尚未返回事件时显示等待，不根据计时编造思考过程或完成百分比。

Codex 的命令 / 文件输出增量与 MCP 工具进度接入会话显示和存储，流式回复、思考和工具事件归一为同一状态。
DeepSeek 复用公共的工具与回复阶段显示。最近 30 次状态保存在当前会话轮次，重新打开可读取。
Claude 的 Bash 普通输出若 CLI 未流式提供，仍以工具结果事件返回；tool_progress 到达时更新工具状态。
42 项后端测试包含在任务完成前读取到重试、思考、工具和输出事件的协议检查；
真实 Claude 2.1.312 另用本地 HTTP 服务验证 529 重试后流式回复，未使用外部 API。

### 切换速度（0.7.14-alpha）

切换时先恢复最近三个会话与各 Agent 模型列表的内存缓存，不复制对话对象；缓存按最近访问淘汰。
本地 API 模型配置与会话读取独立刷新，去掉模型返回后再次加载历史的重复请求，
并抑制前台恢复时重复加载与过期响应覆盖当前会话。会话读取失败不再连续弹出相同错误。
统一列表先返回已保存会话，Claude / DeepSeek 原生会话扫描在后台完成后通知刷新，不阻塞首屏。
Codex Token 用量通过只读索引定位本地日志，不为用量查询额外启动 app-server。
缓存随 App 进程退出释放；首次打开未缓存历史以及真正发送任务仍可能需要 Agent 启动时间。

### Codex 切回恢复（0.7.15-alpha）

修复切回 Codex 时“找不到这个 Codex 会话的本地记录”：首先通过只读索引按 ID 恢复，
不受当前 API 提供方的默认会话列表过滤影响；索引缺失时列出所有提供方并尝试直接恢复。
仅在本地索引不存在且 Codex 明确返回 no rollout found 等不存在信息时，清除失效的界面选择并打开新对话。
不删除历史；进程启动失败、读取权限和其他错误保留原会话选择并报告错误。

## 当前发布范围

当前版本 `0.9.7-alpha`。独立与协作使用单一执行按钮：有文字或附件时发送，执行中输入为空时停止当前执行，停止后输入为空时继续原任务；统一待发队列支持编辑、删除与引入，详见 [队列说明](MESSAGE_QUEUE.md)。安装、检查和更新结果保留在当前操作页，手动收起后隐藏；失败提供对应 Debug 日志入口。API 配置页重建保留当前 Agent，密钥不写入页面恢复状态。协作后端接口见 [接口说明](COLLABORATION_BACKEND_V2.md)。

多参与者协作已接入当前 APK，支持独立成员进程、任务依赖、暂停／停止、重试与执行记录；高级能力的范围仍以[实现规格](../design/COLLABORATION.md)为参考。[底层核验](../design/COLLABORATION_FEASIBILITY.md)使用真实 CLI 和本地模拟 API。

协作聊天直接消费成员事件并复用独立模式的流式归一，思考、命令输出、工具参数与进度在任务完成前更新。执行尝试使用独立条目命名空间和事件序号；整段读取携带相应版本，旧读取结果不覆盖较新的实时内容。协作回合虽不占用普通回合的运行状态，仍按内容变化重新绘制；无输出的命令与工具也显示活动卡片。

## 环境安装与故障定位

安装包仍只内置 Ubuntu 基础系统；Python、Git、TLS/CA、curl、xz、Node.js 与 npm 在初始化时按需下载。依赖补装分为“恢复未完成的软件包配置”“更新软件源”“下载依赖”“解包与配置”“验证运行”，Node.js 分为版本检查、下载、SHA-256 校验、解压与实际运行检查，每步独立超时。不会清空已有 Agent、项目、配置或会话。

初始化默认将 Ubuntu 24.04 ARM64 的 `ubuntu-ports` 源（含 `noble-security`）改为中科大，更新索引或下载失败时尝试清华；首次更改前在 `runtime/source-backups/` 生成 `.aixs-backup`，保留自定义第三方源。基础系统尚无 CA 包，因此 APT 引导使用镜像的 HTTP 地址，仍由 Ubuntu 自带 keyring 验证索引签名与包哈希，不关闭签名校验。Node.js 使用 npmmirror / 清华 HTTPS 镜像，继续按目录内固定的官方 SHA-256 校验；npm、Agent 原生包下载与版本查询使用 npmmirror HTTPS。App 在 GitHub 上的更新服务独立于初始化。

环境检测分别检查 PRoot/Shell、临时目录、Python 启动、标准库／SQLite／ctypes／子进程／字节码编译、TLS CA、Git 本地仓库、curl、xz、Node 文件与子进程、npm 和 dpkg 状态；每项记录超时、最后输出、退出码与可读取的进程状态。实际 Ubuntu 源、国内 Node.js 主／备用源与 npm 的 DNS／TCP／TLS 单独诊断，网络不可达不冒充环境文件损坏。`runtime/health-report.json` 包含实际 APT 配置并随诊断报告导出；证据不足时保留为待定位，不仅凭超时断言某一品牌系统杀后台。
